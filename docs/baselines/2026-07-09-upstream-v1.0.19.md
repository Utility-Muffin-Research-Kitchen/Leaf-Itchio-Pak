# Upstream v1.0.19 regression baseline

This record captures the Leaf fork immediately before runtime-path and renderer
replacement. It is a regression reference, not an MLP1 performance target.

## Source and host

- Fork point: `upstream-v1.0.19` / `42171a5a764ff341d581b6e3ec6cd02adb936eb7`
- Measurement branch: `codex/leaf-port-foundation`
- Host: Apple M5 Pro, arm64, macOS
- Go: `go1.26.5 darwin/arm64`
- Date: 2026-07-09

The untagged host-native SDL executable built successfully with:

```sh
go build -o /tmp/leaf-itchio-upstream-native ./cmd/itchio-pak
```

## Startup memory

`/usr/bin/time -l` around a clean `-headless` startup reported:

| Metric | Result |
|---|---:|
| Wall time | 0.34 s |
| Maximum resident set size | 18,366,464 bytes (17.5 MiB) |
| Peak memory footprint | 4,965,048 bytes (4.7 MiB) |

This includes process and dynamic-library startup but no catalogue, artwork, or
interactive renderer allocation.

## Deterministic latency and allocation baselines

The command below ran each benchmark for 20 iterations, three times:

```sh
go test -tags headless -run '^$' \
  -bench 'Benchmark(FetchFirstFeedPage36|LoadGamesCache1000|CachedCataloguePipeline5000|RenderAnimatedGIF160x90x30)$' \
  -benchmem -benchtime=20x -count=3 \
  ./internal/itchio ./internal/ui ./internal/renderer
```

| Benchmark | Observed time/op | Bytes/op | Allocs/op |
|---|---:|---:|---:|
| Parse first 36-game feed page through local HTTP | 0.413–0.439 ms | 299–301 KiB | 5,024–5,027 |
| Load 1,000-game JSON cache | 1.054–1.112 ms | 640 KiB | 5,024 |
| Filter/search/A-Z sort a 5,000-game cached catalogue | 0.252–0.271 ms | 1,012 KiB | 2,912 |
| Composite/sample 30-frame 160×90 GIF | 0.644–0.670 ms | 1,153 KiB | 28 |

The first-page benchmark intentionally excludes internet latency, which is not
stable enough to compare renderer implementations. It includes the HTTP client,
body read, XML parse, title/tag normalization, and `Game` construction.

## Animated GIF behavior

The pre-port behavior is protected by tests and the benchmark:

- animated images remain multi-frame rather than being flattened;
- at most 16 RGBA frames are retained;
- sampling preserves the total source animation duration;
- zero-delay frames default to 100 ms;
- compositing honors frame bounds and disposal behavior;
- the separate static cover-art path selects a composed, information-rich frame.

The synthetic 30-frame benchmark retained 16 frames and processed 645–670 µs
per animation on the reference host. Catastrophe may change absolute timing,
but must preserve the observable frame order, pacing, and duration rules.

## Interpretation

These numbers isolate code owned by the port and can run in CI. MLP1 device
acceptance later adds real network, SD-card, GPU upload, frame pacing, and peak
working-set measurements. No host number in this file overrides the Phase 11
device gates.
